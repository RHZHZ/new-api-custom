# 登录页面改造设计与实施规范

> 状态：基础布局与动效已实施，浏览器视觉验收待完成  
> 适用路由：`/sign-in` 及共享认证布局  
> 基准日期：2026-07-27  
> 关联规范：`docs/enterprise-website-theme-design.md` 第 16.6、16.8、16.11、16.12 节

## 1. 背景

当前登录页已经具备左右分栏、品牌面、用户名密码登录、Passkey、OAuth、微信登录、法律条款、人机验证、语言切换和主题切换等完整能力。本次改造不调整认证协议、接口或重定向逻辑，只处理视觉层级、信息密度、交互状态、响应式和可访问性。

截图中可见的主要问题：

1. 超宽视口下品牌面与工作面存在大面积无效留白，表单显得偏小、偏散。
2. 表单标题、字段标签、输入框和主按钮的层级差异不足，输入区域与页面背景接近。
3. 顶部返回、语言、主题入口尺寸偏小，命中区域和视觉一致性不足。
4. 左下角直接展示开发环境 `IP:端口`，正式视觉中容易被误认为调试信息。
5. 第三方悬浮工具与页面品牌不一致，并存在遮挡窄屏内容的风险。
6. 截图中的文字存在彩色边缘，需要区分 CSS 效果与截图缩放/系统字体抗锯齿问题后再处理。

## 2. 改造目标

- 将页面定位为安静、可信、清晰的企业级认证入口。
- 保留墨绿品牌面与暖白工作面的核心识别，不改造成营销落地页。
- 登录表单始终是页面唯一主任务，品牌信息不与表单争夺注意力。
- 覆盖完整认证状态，避免加载、报错或第三方登录出现布局跳动。
- 在 `320px` 宽度和极矮视口下仍可完成登录，不产生页面级横向滚动。
- 保留并正确展示所有与 new-api、QuantumNous 相关的项目标识、归属和元数据。

## 3. 非目标

- 不修改登录、2FA、Passkey、OAuth、微信和 Turnstile 的后端协议。
- 不新增虚假的节点数、在线率、请求量或实时运行指标。
- 不为视觉改造增加新的状态管理、动画框架或 UI 依赖。
- 不在认证页增加功能介绍卡片、客户案例、套餐入口或营销轮播。
- 不拆分出仅被单个页面调用、且没有稳定业务含义的辅助组件。

## 4. 设计原则

### 4.1 任务优先

页面只有一个主要操作：完成认证。标题、字段、验证、提交和替代登录方式按自然操作顺序排列。返回、语言和主题属于低频工具，不得获得与登录按钮相同的视觉权重。

### 4.2 克制的品牌表达

品牌面只保留系统名称、定位文案和经过校验的公开域名。可使用细边框几何结构形成识别，但不增加渐变光斑、装饰卡片、伪终端数据或无业务意义的动态粒子。

### 4.3 状态优于装饰

有限的视觉资源优先用于焦点、错误、加载、禁用和成功状态。所有状态必须同时具有文字或可访问语义，不能只依赖颜色表达。

### 4.4 共享骨架

登录、注册、找回密码、重置密码、OTP 和 OAuth 回调继续复用 `AuthLayout`。共享布局负责品牌面、工作面、顶部工具和滚动；各认证 feature 只负责自身表单和业务状态。

## 5. 目标信息架构

```text
AuthLayout
├── DesktopBrandPlane
│   ├── SystemName
│   ├── PositioningCopy
│   ├── VerifiedPublicHost（可选）
│   └── StructuralLine（装饰，不参与语义）
└── AuthWorkSurface
    ├── UtilityActions
    │   ├── BackToHome
    │   ├── LanguageSwitcher
    │   └── ThemeSwitch
    └── SignInContent
        ├── TitleAndSignUpLink
        └── UserAuthForm
            ├── Credentials
            ├── LegalConsent（按配置）
            ├── Turnstile（按配置）
            ├── PrimarySubmit
            └── AlternativeMethods（按配置）
```

顺序是稳定契约。不同认证配置只能控制模块是否出现，不能改变主任务顺序。

## 6. 视觉规格

### 6.1 页面与分栏

| 项目       | 规格                                                     |
| ---------- | -------------------------------------------------------- |
| 页面高度   | `min-height: 100svh`，内容超高时自然滚动                 |
| 品牌面宽度 | 桌面使用 `clamp(360px, 36vw, 560px)`；不在超宽屏无限扩张 |
| 工作面     | 占据剩余宽度，表单在工作面内水平居中                     |
| 表单宽度   | `width: 100%`，`max-width: 420px`                        |
| 桌面内边距 | 品牌面 `48–64px`；工作面至少 `32px`                      |
| 移动内边距 | 左右 `20px`；底部包含安全区                              |
| 分栏断点   | `>= 1024px` 显示品牌面；更窄视口使用品牌栏               |

在 `1440px` 和 `1920px` 宽度下，表单都应以工作面为基准居中，而不是以整个页面为基准居中。表单内容超过可视高度时，工作面改为顶部对齐并保留 `40px` 以上上下间距。

### 6.2 色彩

继续使用现有语义变量，不在组件中扩散硬编码颜色。

| 语义                       | 建议值                                   | 用途               |
| -------------------------- | ---------------------------------------- | ------------------ |
| `--brand-plane`            | `#0D271C`                                | 浅色模式品牌面     |
| `--brand-plane-foreground` | `#F5F7F4`                                | 品牌主文字         |
| `--brand-plane-muted`      | `#B9D8C5`                                | 品牌辅助文字       |
| `--brand-plane-signal`     | `#93D2AD`                                | 公开域名或弱提示   |
| 工作面背景                 | 现有 `--background`                      | 页面背景           |
| 输入框背景                 | 现有输入语义变量，需与工作面形成可见区分 | 表单字段           |
| 主操作                     | 现有 `--primary`                         | 登录按钮、关键链接 |
| 错误                       | 现有 destructive/error 语义变量          | 字段和表单错误     |

深色模式单独校验品牌面、输入背景、边框、占位文字和错误文字，不使用简单反色代替语义变量。

### 6.3 排版

| 元素           | 规格                                     |
| -------------- | ---------------------------------------- |
| 系统名称       | `28–32px`，`font-semibold`，行高 `1`     |
| 品牌定位文案   | `40–48px`，行高 `1.2–1.25`，最多三行     |
| 品牌辅助文案   | `14–16px`，行高不低于 `1.5`              |
| 表单标题       | `28–32px`，`font-semibold`               |
| 注册提示       | `14–16px`                                |
| 字段标签       | `14px`，`font-medium` 或 `font-semibold` |
| 输入文字       | 移动端至少 `16px`；桌面 `15–16px`        |
| 错误与帮助文字 | `13–14px`，行高不低于 `1.4`              |

认证页文字统一使用 `letter-spacing: 0`。表单标题、字段和按钮不得使用重影、发光或故障效果。若彩色边缘只在缩放截图中出现，应记录为渲染环境问题，不通过模糊字体或改变全局字体栈掩盖。

### 6.4 控件尺寸

| 控件         | 规格                                  |
| ------------ | ------------------------------------- |
| 文本输入     | 高 `48px`，圆角沿用全局小圆角体系     |
| 主按钮       | 高 `48px`，宽度 `100%`                |
| 替代登录按钮 | 高度不低于 `44px`                     |
| 图标按钮     | `44 x 44px` 命中区域                  |
| 密码显隐按钮 | 命中区域不小于 `44 x 44px`            |
| 复选框       | 可见控件不小于 `18px`，标签整体可点击 |
| OTP 输入槽   | 不小于 `44 x 44px`                    |

控件 hover 不改变几何尺寸；加载图标、错误文字和长翻译不得推动主按钮横向或造成页面跳动。

### 6.5 动效

- 动效只用于首次进入时建立层级，不持续循环，不影响表单操作。
- 品牌名称在 `360ms` 内轻微下移复位并淡入；品牌文案在 `440ms` 内上移 `12px` 复位并淡入。
- 右侧同色层使用 `500ms` 的横向缩放淡入，变换原点固定在右侧。
- 表单内容在 `360ms` 内上移 `8px` 复位并淡入，不逐字段播放，避免拖慢主要任务。
- 缓动统一使用 `cubic-bezier(0.22, 1, 0.36, 1)`，延迟不超过 `160ms`。
- 动画只在 `prefers-reduced-motion: no-preference` 下启用；减少动态效果模式直接显示最终状态。
- 禁止在认证页增加持续漂浮、粒子、光斑、背景平移、文字故障或循环脉冲效果。

## 7. 页面区域改造

### 7.1 品牌面

- 保留系统名称和“企业级统一服务中转站”定位文案。
- 辅助文案维持一句，避免堆叠能力清单。
- 品牌面右侧使用窄幅同色层增加深度，不模拟卡片边界，也不绘制未闭合的空框。
- `window.location.host` 不应无条件展示。仅在生产环境或值为可识别公开域名时显示；`localhost`、回环地址、链路本地地址、裸 IP 和带开发端口的地址隐藏。
- 不添加实时状态圆点，除非后续接入真实健康状态接口并定义完整错误语义。

### 7.2 顶部工具区

- 返回、语言和主题统一使用 `44 x 44px` 图标按钮和一致间距。
- 每个按钮提供可访问名称；对不熟悉的图标补充 Tooltip。
- 桌面固定在工作面右上角，但与视口边缘至少保持 `20px`。
- 移动端三项工具全部保留。空间不足时优先收紧间距，不隐藏主题切换。
- 返回入口始终回到首页，不依赖浏览器历史，避免从外部链接进入后返回未知页面。

### 7.3 标题与注册入口

- “登录”使用页面主标题语义 `h1`，全页只保留一个 `h1`。
- 注册入口紧随标题说明，不使用独立次级按钮。
- 注册关闭或自用模式下整行隐藏，不保留空白占位。
- 长翻译允许自然换行，不使用固定高度。

### 7.4 凭据表单

- 字段标签始终显示，placeholder 只提供输入示例，不能替代 label。
- 用户名使用合适的 `autocomplete`；密码使用 `current-password`。
- 忘记密码与密码标签同排时，需要为长翻译提供换行或下一行降级，不能覆盖标签。
- 密码显隐按钮保留可访问名称，并同步反映当前显示状态。
- 焦点使用清晰的 `2px` 外圈或等效高对比样式。
- 客户端字段错误显示在对应字段下方；认证失败显示在表单内的稳定错误区域，并保留 toast 作为补充反馈时需避免重复播报。

### 7.5 法律同意与人机验证

- 法律同意只保留 `LegalConsent` 一个权威交互区。
- 未同意时禁用受约束的登录方式，并通过可见文本说明原因。
- Turnstile 放在主按钮之前，窄屏采用响应式尺寸或受控缩放，不能裁切交互内容。
- 外部验证加载失败时提供明确重试或错误提示，不能只留下空白占位。

### 7.6 主按钮与替代登录

- 登录按钮是唯一实心主按钮。
- 提交中保持按钮宽高稳定，展示加载图标和本地化状态文字，并阻止重复提交。
- 替代登录方式统一置于分隔线之后；只渲染后端实际启用的方法。
- 提供商不超过三个时可使用等宽横排；超过三个时使用两列网格或纵向列表。
- OAuth 品牌图标保留原始语义，不统一改成绿色圆形图标。
- Passkey 不受支持时明确说明，不生成无法点击且无原因的禁用按钮。

### 7.7 第三方悬浮工具

- 悬浮客服、翻译或反馈工具不能覆盖表单、错误提示、Turnstile 和主按钮。
- 桌面与右、下边缘至少保持 `24px`；移动端优先折叠为单一入口或移入页面菜单。
- 视觉颜色应使用中性或品牌语义色。若由外部脚本注入且无法定制，应在认证路由隐藏。
- 同类工具不能重复提供与页面语言切换器相同的能力。

## 8. 响应式行为

### 8.1 桌面 `>= 1024px`

- 显示品牌面和完整工具区。
- 工作面表单水平居中。
- 普通高度视口垂直居中；内容过高或视口低于约 `700px` 时顶部对齐并允许滚动。
- 超宽屏品牌面宽度封顶，避免扩大无效留白。

### 8.2 平板 `768–1023px`

- 隐藏侧边品牌面，使用顶部品牌栏。
- 表单宽度仍不超过 `420px`。
- 页面自然滚动，不使用固定 `100vh` 截断内容。

### 8.3 移动 `< 768px`

- 顶部品牌栏高度 `64px`，包含系统名称和三个工具入口。
- 表单从顶部开始排列，左右间距 `20px`，底部保留 `env(safe-area-inset-bottom)`。
- 输入字号不低于 `16px`，避免 iOS 自动放大。
- 替代登录按钮可降为单列；任何提供商名称都不能截断。
- `320px` 宽度不得出现页面级横向滚动。

### 8.4 极矮视口

- 在 `320 x 320`、横屏手机和软键盘弹出状态下，页面必须可滚动至主按钮。
- 顶部品牌栏不使用会遮挡表单的固定定位。
- 聚焦输入后，浏览器滚动目标不能被顶部区域覆盖。

## 9. 状态矩阵

| 状态                | 预期表现                                             |
| ------------------- | ---------------------------------------------------- |
| 初始加载            | 系统名称使用同尺寸骨架，表单结构不跳动               |
| 字段无效            | 字段边框、错误图标/文本和 `aria-invalid` 一致        |
| 凭据错误            | 表单内显示明确错误，焦点或读屏通知可感知             |
| 提交中              | 主按钮尺寸稳定、禁止重复提交                         |
| 网络失败            | 保留已输入用户名，密码处理遵循现有安全策略，提供重试 |
| 法律条款未同意      | 相关方式禁用并提供可见原因                           |
| Turnstile 加载/失败 | 保留稳定区域，失败时可理解、可恢复                   |
| Passkey 不支持      | 显示原因，不触发无效认证请求                         |
| OAuth 关闭          | 不显示对应入口，也不保留分隔线空白                   |
| 仅替代登录          | 隐藏凭据字段和无意义分隔线，替代方式成为主要任务     |
| 注册关闭            | 隐藏注册提示，不改变标题与表单起始位置               |
| 深色模式            | 输入、边框、焦点、错误和提供商图标均清晰可读         |

## 10. 国际化与内容

- 所有用户可见文字继续通过 `useTranslation()` 和 `t()` 输出。
- 新增键同步到 `en`、`zh`、`zh-TW`、`fr`、`ru`、`ja`、`vi` 七种语言。
- 系统名称、OAuth 提供商名称和公开域名按专有名词处理，不强制翻译。
- 文案避免技术实现术语，例如不向普通用户展示 `OAuth callback`、`flow token` 等内部概念。
- 重点检查法语、俄语和越南语下的忘记密码、法律条款、Passkey 不支持提示和按钮宽度。

## 11. 可访问性要求

- 页面使用 `main` 承载认证主内容，品牌面使用 `aside`，工具区使用可理解的导航或工具语义。
- 登录标题使用 `h1`；表单字段使用可关联的 `label`。
- 所有图标按钮具有 `aria-label`；装饰结构设置 `aria-hidden="true"`。
- 键盘焦点顺序与视觉顺序一致：返回/语言/主题 → 注册入口 → 凭据字段 → 条款 → 验证 → 登录 → 替代方式。
- 错误信息通过 `aria-describedby` 或表单组件现有机制与字段关联。
- 正文和控件文字满足 WCAG 2.1 AA；焦点与错误状态不能只通过颜色区分。
- `prefers-reduced-motion` 下关闭非必要加载动画以外的位移和渐变动画。

## 12. 工程实施范围

优先在现有文件中完成改造，不复制认证布局：

| 文件                                                          | 责任                                           |
| ------------------------------------------------------------- | ---------------------------------------------- |
| `web/src/features/auth/auth-layout.tsx`                       | 分栏、公开域名过滤、工具区、语义结构和滚动行为 |
| `web/src/features/auth/sign-in/index.tsx`                     | 页面标题、注册入口和内容间距                   |
| `web/src/features/auth/sign-in/components/user-auth-form.tsx` | 字段、错误、提交、替代登录状态                 |
| `web/src/styles/brand-scopes.css`                             | 认证作用域语义变量和深色模式                   |
| `web/src/features/auth/components/oauth-providers.tsx`        | 提供商数量对应的布局降级                       |
| `web/src/components/password-input.tsx`                       | 密码显隐命中区和可访问状态                     |
| `web/src/i18n/locales/*.json`                                 | 七语言文案同步                                 |

实现约束：

- 不新增页面专用 CSS 文件，认证视觉变量继续集中在 `brand-scopes.css`。
- 不为单一 class 组合创建机械式 helper。
- 不改变认证 API DTO、返回结构和路由查询参数。
- 不删除或替换 new-api、QuantumNous 相关标识、归属和元数据。
- 若第三方悬浮工具由部署注入，使用路由级配置治理，不在认证组件中操作未知 DOM。

## 13. 实施顺序

1. 建立当前 `/sign-in` 的桌面、移动、深色和长内容基准截图。
2. 调整 `AuthLayout` 的品牌面宽度上限、工具按钮、移动品牌栏和极矮视口滚动。
3. 调整标题、字段、主按钮和替代登录方式的排版层级。
4. 补齐字段错误、凭据错误、Turnstile、Passkey 和仅替代登录状态。
5. 处理公开域名显示规则与第三方悬浮工具遮挡。
6. 同步七语言并验证长翻译。
7. 增加布局与交互回归测试，执行类型、lint、构建和浏览器验收。

每一步应保持认证流程可用，避免先重写全部结构再集中修复行为回归。

## 14. 测试要求

建议新增或更新以下测试：

- `web/src/features/auth/__tests__/auth-layout.test.ts`
  - 桌面品牌面与移动品牌栏按断点互斥。
  - 移动品牌栏包含返回、语言和主题入口。
  - 开发地址和裸 IP 不显示，公开域名可显示。
  - 布局使用最小视口高度并允许内容自然滚动。
- `web/src/features/auth/sign-in/__tests__/layout.test.ts`
  - 注册关闭时不保留提示占位。
  - 仅替代登录配置下不显示凭据字段和多余分隔线。

测试应断言用户可见行为和稳定布局契约，不断言完整 Tailwind class 字符串或私有函数调用。

## 15. 浏览器验收

### 15.1 视口

- `1920 x 1080`
- `1440 x 900`
- `1024 x 768`
- `768 x 1024`
- `430 x 932`
- `390 x 844`
- `360 x 800`
- `320 x 568`
- `320 x 320`

### 15.2 必验组合

- 浅色、深色。
- 中文、英文，以及至少一种长文本语言。
- 默认、字段错误、凭据错误、提交中。
- 条款开启、Turnstile 开启、Passkey 开启、多个 OAuth 提供商。
- 注册关闭、密码登录关闭、仅替代登录。
- 键盘完整操作与移动软键盘场景。

### 15.3 验收标准

- 页面无横向滚动，表单和悬浮工具无重叠。
- 表单在工作面内居中，超宽屏品牌面不无限增宽。
- 输入框、主按钮和图标按钮尺寸符合本规范。
- 所有认证方式、重定向和现有配置开关行为保持不变。
- 登录错误可见且可被辅助技术感知，错误出现时主按钮仍在可滚动范围内。
- 七语言无文字裁切、按钮溢出或标签覆盖。
- 浏览器控制台无新增 error，页面无框架错误遮罩。
- 若截图仍有文字彩边，检查 computed style，确认不存在 `text-shadow`、`filter` 或重复渲染；若仅为系统字体抗锯齿或截图缩放产物，记录环境结论即可。
- 受影响测试、TypeScript 类型检查、涉及文件 lint、i18n 同步检查和生产构建全部通过。

## 16. 完成定义

满足以下条件后，登录页改造才视为完成：

1. 本文列出的桌面、移动和极矮视口行为全部实现。
2. 密码、Passkey、OAuth、微信、2FA、条款和 Turnstile 的现有流程无回归。
3. 布局与交互回归测试覆盖本次新增契约。
4. 七语言、浅深主题和键盘操作完成浏览器验收。
5. 不存在开发地址裸露、第三方浮层遮挡、文字裁切或页面级横向滚动。
6. 工程检查全部通过，并保留受保护的项目标识与归属信息。
