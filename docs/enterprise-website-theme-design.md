# RAPI 企业中转站全站主题设计方案

## 1. 文档目标

本文分阶段定义 New API 默认站点的企业化主题改造方案。官网企业品牌为 **RAPI**，公开地址为 **cccc.asia**。第 1–15 章记录公开首页及其公共页头、页脚的第一阶段改造；第 16 章将同一品牌系统扩展到公共内页、认证流程、用户控制台与管理控制台。所有阶段均只调整信息呈现、交互布局与视觉样式，不改变既有路由、权限、接口、计费、认证、自定义内容或数据行为。

设计目标是让页面更接近企业基础设施、云服务与技术采购场景，而不是常见的 AI 产品官网。页面需要传达四个关键词：稳定、可控、透明、易交付。

## 2. 用户与业务目标

### 2.1 主要用户

- 需要统一管理多个上游服务的企业技术负责人。
- 关注权限、成本、可用性与审计能力的运维和管理人员。
- 需要快速完成标准接口接入的开发团队。
- 评估自托管、团队协作和服务治理能力的采购决策者。

### 2.2 首页核心任务

1. 在首屏说明产品是什么：企业级统一接口接入与运营平台。
2. 在首屏给出明确入口：未登录用户注册或查看定价，已登录用户进入控制台。
3. 用可验证的能力表达替代抽象概念：统一接入、流量治理、权限管理、成本核算、运行监控。
4. 让技术用户快速理解接入路径，让管理用户快速理解治理价值。

## 3. 设计方向

### 3.1 核心概念：企业运营中枢

页面采用“运营中枢”而不是“智能未来”作为视觉叙事。首屏右侧展示服务运行总览，后续区块依次说明接入规模、治理能力、交付流程与行动入口。

整体气质参考成熟 B2B 基础设施产品：克制、清晰、信息可信。通过严谨的网格、表格、状态行和细分隔线建立专业感，不依赖炫光、宇宙背景或抽象生成式插画。

### 3.2 明确避免

- 不使用 AI、机器人、大脑、星空、宇宙等视觉隐喻；粒子网络自 2026-07-26 起按第 3.3 节的约束作为首屏唯一例外。
- 不使用紫蓝渐变标题、发光光晕、渐变球、网格背景和玻璃拟态。
- 不使用首屏胶囊标签、夸张口号或“连接未来”类空泛文案。
- 不把终端代码作为首屏主视觉，不以模型品牌列表作为核心卖点。
- 不使用大圆角漂浮卡片、卡片套卡片和重复 Bento 网格。
- 不使用无法证实的 SLA、客户数量、请求成功率等虚构数据。

### 3.3 方向修订：首屏粒子动效（2026-07-26）

应站点所有者要求，首屏引入「丰富粒子网络」动效以强化表现力。为使其与企业气质兼容而非退回通用 AI 官网，约束如下：

- 仅出现在公开首页首屏（`features/home/components/particle-field.tsx`，由 `sections/hero.tsx` 挂载），不进入公共内页、认证页与控制台。
- 只使用品牌绿（浅色 `#164A35`/`#176B47`、深色 `#93D2AD`），禁止紫蓝渐变与多色霓虹；粒子与连线透明度控制在低对比区间，不得影响正文对比度。
- 组成（2026-07-26 第二次修订，改为 3D 电影感场景）：手写透视投影的「粒子地球」——斐波那契球面点云缓慢自转、前后半球景深明暗分层，9 条跨球面大圆弧上飞行请求脉冲（隐喻全球模型流量经 RAPI 中转），远景视差星尘与指针视差镜头；`aria-hidden` 纯装饰，`pointer-events: none`。
- 工程约束：原生 Canvas 手写 3D 投影，不引入 three.js 等新依赖；球面点数按面积 700–1400 自适应；DPR 上限 2；标签页隐藏时暂停；组件卸载完整清理监听与 RAF。
- `prefers-reduced-motion: reduce` 时完全不渲染动效；两案对比样机存档于 `output/concepts/rapi-site-v1/hero-motion-options.html`（A 请求流 / B 粒子网络，本次采用 B 并保留 A 备选）。
- 第三次修订（2026-07-26）：首屏升级为全屏深色电影布景——浅深两种模式统一使用近黑绿 `#0A130E` 首屏底色，粒子地球与请求光弧作全幅背景，品牌字标 `#93D2AD`、标题白色、正文 `white/65` 叠印于场景之上，主操作改亮绿实底；粒子场固定使用亮绿配色。首屏以下区块仍遵循原浅色编辑式体系。
- 第四次修订（2026-07-26）：站点所有者要求缩小地球并改为「真实地球模型 + 粒子环绕」，并批准为此新增依赖。最终实现未动用该豁免：改为手写 WebGL 渲染管线（`globe-scene.ts`，约六个小型着色器），零新依赖，第 10 章禁新依赖条款保持不变。构成：实心暗色球体 + 大气边缘辉光；真实海岸线点阵大陆（人工描摹全球海岸线多边形经 1.5° 球面网格采样烘焙为 `earth-dots.ts`，约 5300 点，海岸线点高亮）；三条不同倾角/半径/转速/方向的粒子轨道环（96–112 点/环，彗尾脉冲，经深度测试正确穿越星球前后）；六条真实城市间请求光弧（北京—旧金山、上海—东京、新加坡—悉尼、北京—法兰克福、迪拜—新加坡、伦敦—纽约）；视差星尘。球心置于画布 40%/55% 处，半径 0.30×min(宽,高)，自转约 57 秒/圈，初始朝向亚洲。约束沿用：仅首页首屏、品牌绿单色、DPR≤2、隐藏暂停、卸载清理；`prefers-reduced-motion` 时渲染单帧静态画面（不再完全空白，保证内容完整性）。若未来需要照片级贴图地球，再行启用依赖豁免（three.js + 贴图资产）。
- 第五次修订（2026-07-26）：地球由全幅背景层升格为首屏右侧主视觉——文案居左、完整地球（含全部轨道环）居右，画布仅覆盖首行；`RAPI API` 架构图整体下移为首行之下的全宽区块（居中 max-width 1080px），随滚动进入视野。横屏球心 67% 宽 / 50% 高、半径 0.34×min(宽,高)；竖屏文案堆叠后地球锚定画布底部（半径 0.36×宽、球心距底 1.3 倍半径，短画布回退 55% 高），不再与字幕/按钮相叠，因而取消移动端降不透明度处理。§4.2 的"右侧内容：服务运行总览"相应让位于地球，架构图承接该职能。
- 第六次修订（2026-07-27）：移动端（<1024px 堆叠布局）地球改为标题背景——锚定画布顶部（球心 0.58 宽 / min(1.1R+56px, 0.5 高)），叠印于大号品牌字标与 H1 之下，画布整体 70% 不透明度保证正文可读，底部预留区取消；桌面端不变。文案去重：暗区原有三段近似表述（架构图描述段、区块副文、独立标语带）合并为一——删除页尾标语带，其文案「一个接口，一把密钥，每个请求清晰可见」升为架构图区块副文，`cccc.asia` 外链随之移入区块头部右栏；'Model capabilities connect on one side…' 键保留于语言包备用。

## 4. 信息架构

首页保留五个主要区块，调整现有区块语义与版式。

### 4.1 公共页头

- 左侧：动态站点 Logo 与名称。
- 中部：沿用后台配置或默认导航。
- 右侧：语言、主题、通知与登录入口。
- 桌面端为固定高度横向导航；滚动后保持矩形轻边框形态，不收缩成悬浮胶囊。
- 移动端保留现有全屏菜单与认证流程。

### 4.2 首屏：统一接入，集中治理

左侧内容：

- H1：`RAPI`
- 定位标题：`企业级统一服务中转站`
- 说明：`通过一个兼容接口接入多种模型服务，使用统一密钥，并在开发到生产的全过程清晰掌握用量、余额与请求。`
- 主操作：未登录显示“立即开始”，已登录显示“进入控制台”。
- 次操作：“查看定价”。
- 文本链接：“阅读接入文档”。
- 公开地址：`cccc.asia`。
- 三项简短能力：统一接口、精细权限、用量可追溯。

右侧内容：

- 名称：`服务运行总览`。
- 展示三个真实产品概念，不请求后端实时数据：渠道状态、今日用量、预算使用。
- 展示三个运营行：请求调度、权限策略、用量记录，状态统一为“正常”。
- 这是静态能力示意，不伪装成实时监控，不展示虚构百分比 SLA。

首屏高度：

- 桌面端首屏主体最小高度约 `680px`，在 768px 高视口中露出下一段数据条。
- 移动端不锁定视口高度，内容自然排列，右侧总览位于操作区下方。

### 4.3 规模数据条

沿用当前可证明的产品适配数量：

- `50+` 上游服务适配
- `100+` 模型计费支持
- `50+` 兼容接口路由
- `10+` 调度控制能力

表现形式改为带纵向分隔线的开放式数据带，不使用大号渐变数字或独立卡片。计数动画可保留，并遵循减少动态效果偏好。

### 4.4 核心能力：从接入到运营

使用四行开放式能力清单，每行由编号、标题、说明、图标和一条业务结果组成：

1. 统一接入：以兼容接口降低不同上游的接入和迁移成本。
2. 稳定调度：通过优先级、权重、重试与限流提高服务连续性。
3. 权限治理：按用户、令牌和分组管理调用范围与额度。
4. 成本运营：统一记录用量、计费与日志，支持核算和追溯。

桌面端采用两列分区：左侧固定章节标题，右侧为能力行列表。移动端改为单列。能力行仅用细分隔线，不使用卡片背景。

### 4.5 交付流程：三步投入使用

采用横向流程轨道，而不是三个图标卡片：

1. 配置资源：添加上游渠道并设置分组与权限。
2. 切换地址：使用兼容接口和统一凭据接入现有应用。
3. 持续运营：查看用量、成本、日志和运行状态。

每一步包含编号、标题、说明和交付结果。桌面端通过细线连接，移动端改为纵向时间线。

### 4.6 行动区与页脚

- 标题：`让服务接入更简单，让运营管理更清晰`
- 说明：`从统一接口开始，逐步建立可管理、可核算、可扩展的服务基础设施。`
- 操作：立即开始、查看定价。
- 行动区使用深色实底横幅，避免渐变和装饰光效。
- 已登录用户不展示行动区，保持现有行为。
- 页脚保留动态站点信息、法律链接和项目归属信息，不改动项目品牌与归属。

## 5. 视觉系统

### 5.1 色彩

主题以中性黑白灰为基础，使用低饱和企业绿色作为唯一主要强调色，并以琥珀色表示成本类信息。

| 用途       | 浅色模式  | 深色模式  |
| ---------- | --------- | --------- |
| 页面背景   | `#FFFFFF` | `#111411` |
| 次级背景   | `#F5F7F5` | `#181C18` |
| 主要文字   | `#172019` | `#F2F5F2` |
| 次级文字   | `#5F6B62` | `#AAB4AC` |
| 边框       | `#DCE2DD` | `#303730` |
| 主强调色   | `#176B47` | `#46A879` |
| 主强调悬停 | `#105739` | `#5BB98B` |
| 成本提示   | `#A86514` | `#D49A4A` |

规则：

- 不使用渐变填充和多色背景。
- 强调色面积控制在页面可见面积的 10% 以下。
- 状态颜色必须同时配合文字或图标，不单独依赖颜色传达状态。
- 不修改全局主题变量，首页使用局部语义类，避免影响后台控制台。

### 5.2 字体

- 使用项目现有 `Public Sans` 与系统中文无衬线回退，不新增字体依赖。
- H1：桌面 `52px/1.12`，移动 `36px/1.16`，字重 650 至 700。
- H2：桌面 `34px/1.2`，移动 `28px/1.25`。
- 正文：`16px/1.75`；辅助正文 `14px/1.65`。
- 控件：`14px/1`，字重 600。
- 不使用负字间距，英文小标签不使用大幅扩展字距。

### 5.3 布局与间距

- 主内容最大宽度：`1184px`。
- 桌面页面边距：`32px`；平板 `24px`；移动 `20px`。
- 区块垂直间距：桌面 `104px`，移动 `72px`。
- 基础间距序列：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 80 / 104`。
- 内容优先使用开放式布局与分隔线；只有运行总览和最终行动区使用明确容器。

### 5.4 圆角、边框与阴影

- 按钮、输入和小型状态元素：`6px`。
- 运行总览与行动横幅：`8px`。
- 不使用超过 `8px` 的官网卡片圆角。
- 边框统一 `1px`，不使用半透明叠层制造玻璃效果。
- 阴影仅用于页头滚动态和首屏总览：`0 16px 40px rgb(20 31 23 / 8%)`。

### 5.5 图标

- 继续使用项目已有 `lucide-react`。
- 图标统一 `18px` 或 `20px`，`strokeWidth={1.75}`。
- 图标只用于解释能力或操作，不作为大面积装饰。
- 按钮中的箭头、文档等操作使用对应图标并提供可访问名称。

### 5.6 动效

- 首屏采用轻微淡入和不超过 `12px` 的位移，不使用模糊入场。
- 区块滚动出现可沿用 `AnimateInView`，持续时间控制在 `400ms` 左右。
- 悬停只改变边框、背景或箭头位置，不缩放卡片。
- 保留 `prefers-reduced-motion` 降级路径。

## 7. 响应式规则

### 7.1 桌面端（`>= 1024px`）

- 首屏为 `7 / 5` 栅格，左侧文本更宽，右侧总览固定稳定宽度。
- 能力区为左侧章节说明、右侧能力列表。
- 流程区为三列横向轨道。

### 7.2 平板（`768px - 1023px`）

- 首屏改为单列，总览宽度铺满但限制最大高度。
- 数据条保持四列，缩小间距。
- 能力区与流程区转为单列或两列，避免文字拥挤。

### 7.3 移动端（`< 768px`）

- 首屏主次操作纵向排列并占满宽度，文档入口保持文本按钮。
- 运行总览横向内容不得溢出，表格型信息改为两行布局。
- 数据条为两列，两行之间有边框分隔。
- 能力列表不展示冗余编号装饰，保留图标、标题与结果。
- 流程区为纵向时间线。
- 最长翻译文案允许自然换行，按钮高度保持稳定。

## 8. 国际化与内容策略

- 所有新增可见文案使用 `useTranslation()` 与 `t('English key')`。
- 英文键是语义完整的源文案；同步维护 `en`、`zh`、`zh-TW`、`fr`、`ru`、`ja`、`vi`。
- 中文文案以企业采购和运营语境为准，不直译 AI 营销术语。
- `AI` 仅在必须描述兼容产品类别时出现，首页主要标题和区块标题不使用该词。
- 动态站点名称、Logo、文档链接和导航配置继续来自现有系统配置。

## 9. 可访问性

- 使用 `header`、`nav`、`main`、`section`、`footer` 等语义结构。
- 每个 `section` 通过可见标题或 `aria-labelledby` 建立名称。
- 交互按钮具备清晰焦点态，焦点颜色与背景对比度满足 WCAG 2.1 AA。
- 装饰图标设置 `aria-hidden="true"`；状态行包含可读文本。
- 移动菜单继续维护 `aria-label` 与键盘可操作性。
- 动画在减少动态效果偏好下关闭。

## 10. 实现约束

- 保留自定义首页 URL、HTML、Markdown 三种加载分支；只改默认首页。
- 不改动后端接口、数据库和系统设置模型。
- 不修改 New API、QuantumNous 相关品牌、版权、许可和项目归属信息。
- 不引入新依赖，不写入远程图片 URL，不增加不可控第三方资源。
- 不创建仅为缩短代码而存在的单次调用 helper。

## 15. 移动端模型接入架构重构

本章定义第三轮视觉方案的移动端专项基线，仅适用于 `< 768px` 视口。其目标不是压缩桌面拓扑，而是用更短、更清晰的用户路径说明“支持哪些模型类型、通过什么接口接入、用户能获得什么”。当本章与第 4.2、7.3、14.1 或 14.3 节的移动端描述冲突时，以本章为准；`>= 768px` 的桌面与平板大屏结构保持不变。

### 15.1 重构原因与设计目标

当前移动端将桌面模型拓扑直接纵向排列，在约 `390px` 宽度下存在以下问题：

- 五种模型类型换行为不平衡的 `3 + 2` 网格，第二行产生明显空位。
- 纵向 `RAPI CONTROL / API` 色块占用过多高度，品牌层级高于用户收益。
- 四项能力依次纵向排列，单项信息量少但留白大，整体接近两屏高。
- 模型标签、能力标题与说明使用约 `9–10px` 字号，阅读成本过高。
- 桌面连接线、治理行和重复输出类型在手机端信息价值有限，却持续拉长页面。
- 固定页头与模型标题条距离过近，滚动或首屏定位时容易出现遮挡和语义缺失。

移动端重构遵循三个原则：

1. **用户收益优先**：使用“统一接口、API 密钥、稳定调用、用量与余额”，不使用“上游渠道、控制平面、调度治理”等站点运营语义。
2. **一屏完成理解**：用户在一次视线扫描中看完模型类型、RAPI 接入层和四项核心能力。
3. **独立信息架构**：保留桌面版表达的业务关系，但不保留其全部装饰、连接线和重复层级。

### 15.2 移动端信息架构

移动端架构模块采用“模型类型轨道 + 接入分隔带 + `2 x 2` 能力矩阵”的固定顺序：

```text
[ 文本 | 图片 | 音频 | 视频 | 工具 ]  80px
[              RAPI API             ]  56px
[ 统一接口          | API 密钥       ]  128px
[ 稳定调用          | 用量与余额     ]  128px
```

- 模型类型在 `360–767px` 范围内保持单行五列，禁止再次形成 `3 + 2` 换行。
- `RAPI API` 改为横向分隔带，作为模型类型与用户能力之间的唯一品牌节点。
- 四项能力使用共享边框的 `2 x 2` 开放矩阵，不创建四张独立卡片。
- 移动端不再重复底部 API 类型轨道；`RAPI API` 已完整表达统一输出关系。
- 模块上下各保留约 `20px` 呼吸空间，中文环境目标总高度约 `432px`，所有语言均应控制在 `420–500px`。

### 15.3 内容与文案

| 区域     | 标题或标签                     | 用户端说明                                   |
| -------- | ------------------------------ | -------------------------------------------- |
| 模型类型 | 文本、图片、音频、视频、工具   | 只说明可接入的内容类型，不出现上游渠道术语   |
| 接入层   | `RAPI API`                     | 品牌固定文案，不翻译，不增加控制或治理副标题 |
| 能力 1   | 统一接口                       | 使用一套兼容接口调用多类模型                 |
| 能力 2   | API 密钥                       | 按项目创建密钥，凭据由你管理                 |
| 能力 3   | 稳定调用                       | 清晰查看模型状态，调用更安心                 |
| 能力 4   | 用量与余额                     | 随时查看余额、用量与请求记录                 |

移动端隐藏以下桌面次级信息：

- `SOURCES / CONTROL / ENDPOINTS`、`Models` 等内部架构标签。
- 模型与接入层之间的纵向连接线、端点方块和纯装饰轨道。
- “身份验证 / 额度 / 余额 / 计费”治理行。
- “状态 / 日志 / 模型 / 请求”运营行。
- 与顶部模型类型相同的底部输出类型及重复说明。

隐藏只影响移动端的信息密度，不删除对应功能，也不改变桌面端现有结构。所有可见文案继续通过 i18n 输出；翻译应优先缩短语句，禁止通过缩小字号或省略号处理长文案。

### 15.4 尺寸与排版基线

| 元素             | 移动端基线                                                     |
| ---------------- | -------------------------------------------------------------- |
| 页面水平边距     | `20px`；安全区额外使用 `env(safe-area-inset-*)`                |
| 架构模块最大宽度 | `560px`，在较宽手机上居中                                      |
| 模型类型轨道     | 高 `80px`，五列等宽；图标 `20px`，标签 `12px/16px`             |
| `RAPI API` 分隔带 | 高 `56px`；文字 `14px/20px`、字重 650                         |
| 能力矩阵         | 两列等宽，共享 `1px` 外框与内部十字分隔线                      |
| 单项能力         | 最小高 `128px`，内边距 `16px`，内容左对齐                      |
| 能力图标         | `20–22px`，`strokeWidth` 约 `1.5`                              |
| 能力标题         | 不小于 `14px/20px`，字重 650，不使用全大写                     |
| 能力说明         | 不小于 `12px/18px`，最多三行；允许单元格随翻译自然增高          |
| 分隔线           | 浅色模式 `rgb(17 22 19 / 16%)`，深色模式 `rgb(255 255 255 / 16%)` |

视觉规则：

- 沿用第三轮暖白、矿物绿和近黑绿色，不为移动端新增颜色。
- `RAPI API` 使用矿物绿实底与白色文字；不使用渐变、阴影、发光或圆角容器。
- 能力矩阵是一个整体结构，单元格之间只用细线分隔，不添加独立背景和悬浮效果。
- 图标放在单元格左上方，标题与说明左对齐，避免当前居中长列造成的松散感。
- `12px` 仅用于本架构内的紧凑说明文字，是第 5.2 节辅助正文字号的局部例外；页面常规正文仍保持 `14px` 以上。

### 15.5 断点与降级规则

#### `< 360px`

- 模型类型轨道改为单行横向滚动，每项最小宽度 `68px`，不得换行。
- 滚动仅发生在模型轨道内部，页面本身不得出现横向滚动。
- 能力矩阵仍保持两列；单元格可随翻译增长到约 `152px`，不截断正文。

#### `360–767px`

- 五种模型类型使用稳定的五列等宽布局，在 `390px` 宽度下应全部直接可见。
- 能力矩阵保持 `2 x 2`，不因横屏或较宽手机改成四列。
- 模块宽度超过 `560px` 后停止增长并居中，维持可扫描的行长。

#### `>= 768px`

- 继续使用现有桌面拓扑、连接线和信息层级，本次移动重构不得造成桌面视觉回归。

长翻译使用 `overflow-wrap: anywhere` 与自然增高处理。标题最多两行，说明最多三行；若某语言仍超出目标高度，应先优化该语言文案，不得降至 `12px` 以下或隐藏关键信息。

### 15.6 首屏与固定页头衔接

- 移动页头目标高度为 `64px`，菜单与主题按钮的可点击区域不小于 `44 x 44px`。
- 首页内容必须从页头实际占位之后开始，架构模块不得使用负外边距进入固定页头区域。
- 在 `390 x 844` 视口中，第一视口底部应露出至少 `56–80px` 的模型类型轨道，提示后续存在可继续浏览的产品结构。
- 为满足上述目标，移动端首屏正文不设置桌面式 `600px+` 强制最小高度；品牌、标题、说明和操作区按内容自然排布。
- 页面滚动到架构模块时，模型类型轨道的首行必须完整可见，不能只留下无标题的深色横条。

### 15.7 可访问性与交互

- 模型类型使用语义列表，图标设置 `aria-hidden="true"`，文字标签始终可见。
- 模型类型与四项能力均为信息展示，不伪装为可点击按钮，不添加无意义悬停态。
- `< 360px` 的横向滚动容器提供可访问名称，并支持触摸、触控板和键盘滚动。
- 文字与背景对比度满足 WCAG 2.1 AA；状态含义不得只依靠绿色表达。
- 减少动态效果偏好下关闭轨道入场和连接动画；布局本身不依赖动画才能理解。
- 页头固定控件、浏览器安全区和正文之间不得重叠；开发环境的 TanStack Router 悬浮工具不计入正式产品布局。

## 16. 全站页面视觉同步方案

本章定义 RAPI 首页之外页面的统一改造基线。当前状态为 **设计待确认**：本章批准前只更新文档，不修改其他页面代码；批准后仍需先完成代表页面概念图并确认，再按第 16.15 节分阶段实现。

当本章与第 1、5–7、10–12 或 15.8 节的范围描述冲突时，以本章为后续阶段基线。首页继续以第 14–15 章及现有概念图为准，不在全站同步阶段重新解释。

### 16.1 改造范围与非目标

“同步改造”指统一品牌信号、页面骨架、视觉变量、组件几何、状态反馈、响应式与用户端文案。覆盖范围按页面责任分为五组：

| 页面层 | 代表路由或模块 | 改造重点 |
| ------ | -------------- | -------- |
| 公共层 | `/pricing`、`/pricing/$modelId`、`/rankings`、`/about`、协议页 | 延续首页品牌，移除生成式装饰，建立任务导向的信息页 |
| 认证层 | 登录、注册、找回、重置、OTP、OAuth 回调 | 统一品牌入口、表单层级、校验与多认证方式状态 |
| 用户控制台 | `/dashboard/*`、`/keys`、`/usage-logs/*`、`/wallet`、`/profile`、Playground、Chat | 提高扫描、筛选、接入、查询和账户操作效率 |
| 管理控制台 | `/channels`、`/models/*`、`/users`、兑换码、订阅、系统信息、系统设置 | 保持高密度运营结构，统一表格、表单、状态与危险操作 |
| 特殊层 | `/setup`、错误页、自定义 URL/HTML/Markdown、外部文档 | 只同步安全外壳、加载与回退状态，保留内容和沙箱边界 |

本阶段明确不做以下事项：

- 不修改后端接口、请求参数、缓存、数据库、权限角色、配额、支付、计费和结算逻辑。
- 不改变 TanStack Router 路由、搜索参数、登录后重定向、模块开关或外部文档跳转规则。
- 不删除、隐藏、替换 New API、QuantumNous 的许可、归属、项目链接、元数据或页脚信息。
- 不重写用户配置的 HTML、Markdown、URL 或 iframe 内容；只处理其外层导航、留白、加载、错误与移动尺寸。
- 不引入新字体、图标库、图表库或页面框架；继续使用 React、Tailwind、Base UI、lucide/Hugeicons 与现有图表组件。
- 不为了统一外观把数据表改成营销卡片、把设置表单改成展示页，或给每个区块增加容器。

### 16.2 用户角色与文案边界

页面文案必须与当前访问者的任务一致：

| 角色 | 主要任务 | 允许使用的语义 |
| ---- | -------- | -------------- |
| 访客 | 看模型、价格、趋势与服务说明，完成注册或登录 | 模型、接口、价格、可用状态、使用趋势 |
| 普通用户 | 创建密钥、发起请求、查看余额与用量、维护账户安全 | API 密钥、请求记录、用量、余额、凭据、模型状态 |
| 管理员 | 配置渠道、模型、用户、计费与站点策略 | 渠道、调度、倍率、分组、供应商、系统设置 |
| 超级管理员 | 维护系统级配置与运行信息 | 数据库、缓存、迁移、系统信息、安全策略 |

用户端页面不得出现“集中管理上游渠道”“控制平面”“治理核心”等站长视角说明；这些术语只保留在管理员可见区域。公开页和普通用户控制台采用以下默认命名：

| 当前概念 | 用户端建议文案 |
| -------- | -------------- |
| Model Square | 模型与价格 |
| Rankings | 使用趋势 |
| Dashboard | 用量分析 |
| Usage Logs | 请求记录 |
| Wallet | 余额与充值 |
| Profile | 账户与安全 |

建议文案只作为新增 i18n 源文案基线，不能直接硬编码中文。英文源键必须语义完整，并同步维护 `en`、`zh`、`zh-TW`、`fr`、`ru`、`ja`、`vi`。

### 16.3 统一设计策略

全站共享“企业基础设施”气质，但不把首页构图机械复制到控制台：

1. **公共页：编辑式信息层。** 延续暖白、矿物绿、直线分区和明确标题层级，强调品牌与可信信息，不使用 AI 插画、径向渐变、光晕、玻璃拟态和超大空白。
2. **认证页：克制的品牌入口。** 让表单成为唯一主要任务，以深绿品牌侧栏和开放式表单建立识别，不创建悬浮登录卡片或装饰性仪表盘。
3. **控制台：安静的运营工作台。** 使用冷中性底色、白色工作面、细边框和紧凑排版，优先表格、列表、图表与表单的扫描效率，不使用首页的大字号、暖白大色块和营销式区块节奏。
4. **共享识别：同一几何和交互。** 三类页面共享 RAPI 字标、矿物绿主操作、`4–6px` 圆角、细线分隔、图标规格、焦点态和状态色语义。
5. **多色只服务数据。** 品牌仍以矿物绿为主，但信息、成本、警告和危险分别使用蓝、琥珀与红；图表不得全部变成绿色，也不得使用紫蓝生成式渐变。

禁止在同步过程中新增机器人、大脑、星空、粒子、生成光效、终端假数据、虚构 SLA、假客户数或无法从接口得到的指标。页面高级感来自版式、比例、密度与内容秩序，而不是装饰数量。

### 16.4 作用域与视觉变量

为避免逐页复制颜色和无边界修改全局主题，实现时使用三个根级语义作用域：

- `public`：由 `PublicLayout` 持有，覆盖公共页品牌画布。
- `auth`：由 `AuthLayout` 持有，覆盖完整认证流程。
- `app`：由 `AuthenticatedLayout` 持有，只定义结构和语义别名，不覆盖用户主动选择的非默认主题预设。

- 默认主题可调整为上述工作台基线；用户选择其他主题预设时，颜色选择必须继续生效，布局、密度和组件几何仍保持一致。
- 不改变主题、字体、圆角、密度和内容宽度设置的持久化逻辑，也不移除配置抽屉。
- 状态颜色必须同时配合文字或图标；图表颜色按系列稳定映射，不能随刷新改变含义。
- 阴影只允许用于模态层、浮层和必要的固定栏分离；普通面板依赖底色与边框，不悬浮。

### 16.5 排版、几何与密度

| 元素 | 公共页 | 认证页 | 控制台 |
| ---- | ------ | ------ | ------ |
| 页面标题 | 桌面 `36px/44px`，移动 `28px/36px` | `28px/36px` | 桌面 `20px/28px`，移动 `18px/26px` |
| 区块标题 | `24–30px` | `18–20px` | `15–17px` |
| 正文 | `15–16px/1.7` | `14px/1.6` | `13–14px/1.5` |
| 控件文字 | `14px` | `14px` | `13–14px` |
| 表格文字 | 不适用或 `14px` | 不适用 | `13px/18px`，数字使用等宽数字 |
| 页面边距 | `20/24/40px` | `20/32/64px` | `12/16/24px` |
| 主要圆角 | 容器 `0–4px`，控件 `4px` | 表单控件 `4px` | 面板 `6px`，控件 `4–6px`，上限 `8px` |

补充规则：

- 字号只能按断点切换，禁止使用 `vw` 或 `clamp(...vw...)` 随视口连续缩放。
- 字间距保持 `0`，不使用负字间距；表格数字与金额使用 `tabular-nums`。
- 控制台桌面表格行高目标 `44px`，触摸场景最小 `48px`；移动图标按钮点击区不小于 `44 x 44px`。
- 控制台展开侧栏沿用 `13rem`，折叠宽度沿用 `2.75rem`；不为了“高级”扩大导航占用。
- 内容宽度按任务选择：阅读页 `800–880px`，常规工作台 `1280px`，宽表格与分析页可铺满可用空间。
- 信息面板不得嵌套卡片。面板内分区使用标题、留白、分隔线或表格行表达。

### 16.6 共享页面骨架

#### 公共骨架

- 公共内页使用稳定固定页头：移动端 `64px`、桌面端 `72px`，不沿用首页未滚动时的 `104px` 展示高度，也不在滚动阈值改变高度。
- RAPI 字标、导航、语言、主题和登录状态与首页保持一致；内页当前路由使用文字或底边状态，不使用胶囊背景。
- 内容从固定页头真实高度之后开始，首个区块不得使用负外边距或被页头遮挡。
- 公共内容页有页脚；全屏嵌入内容可只保留页头，但必须维持安全高度和 iframe 沙箱。
- 首页与公共子页使用显式布局变体，禁止继续通过站点名称、Logo 内容或 URL 字符串推断视觉模式。
- `PublicLayout` 始终负责页头占位、语义化 `main`、背景和可选页脚；全宽 HTML、iframe、定价与趋势页也不能绕过这些责任。
- 公共页粘性筛选或工具栏的顶部偏移为“实际页头高度 + `16px`”，不能使用会被固定页头覆盖的固定 `top-4`。

#### 认证骨架

- 桌面使用约 `36 / 64` 双区布局：左侧深绿品牌面承载 RAPI、`cccc.asia` 与简短定位；右侧暖白表单面承载唯一认证任务。
- 表单列宽 `400–440px`，不放入大圆角悬浮卡片；标题、说明、字段、提交、辅助入口按单列排列。
- 移动端移除整块侧栏，顶部保留 `64px` 品牌栏，表单从其下方自然滚动；键盘弹出时提交按钮和错误信息仍可见。
- 登录、注册、找回、重置、OTP、OAuth 回调和安全验证共用同一骨架，不各自创造视觉模板。
- 根容器使用 `min-h-svh` 与自然滚动，不使用会裁切长注册表单或被软键盘挤压的固定 `h-svh`。

#### 控制台骨架

- 应用页头：桌面高 `48px`，移动高 `56px`；左侧为侧栏触发与系统品牌，右侧按搜索、通知、语言、外观、账户的稳定顺序排列。
- 应用侧栏：分组标签弱化，活动项使用左侧 `2px` 标记与浅底色；不使用整块高饱和绿色选中态。
- 页面标题栏：标题左对齐，主要操作右对齐；移动端操作过多时只保留主要操作，其余进入菜单。
- 内容区只保留一个滚动责任者。固定表格页由表格容器滚动，普通页面由内容区滚动，禁止页面与内部面板同时抢占纵向滚动。
- 面包屑只用于系统设置等层级页面；一级工作台不重复显示侧栏名称与无意义路径。

共享骨架应优先落在 `PublicLayout`、`AuthLayout`、`AuthenticatedLayout`、`AppHeader`、`AppSidebar`、`SectionPageLayout` 和数据表组件中。禁止在每个页面重复同一组品牌颜色、边距和标题栏类名。

### 16.7 公共页面规范

#### 模型与价格 `/pricing`

- 移除当前三层径向渐变、居中超大标题和 `clamp(...vw...)` 字号。
- 页面顶部改为紧凑任务头：左侧标题“模型与价格”和说明“查看可用模型、计费方式与接口支持”；右侧或下一行放搜索。
- 桌面 `>= 1280px` 保持左侧筛选栏与右侧结果区；筛选栏宽约 `280–304px`，使用开放分区和细线，不包成大圆角卡片。
- 结果工具栏固定展示结果数、排序、计价单位和列表/表格视图；次级筛选在移动端进入抽屉。
- 表格视图用于快速比较，卡片视图只用于重复模型条目。模型卡圆角不超过 `6px`，不做抬升悬停；点击后仍打开现有详情抽屉。
- 详情抽屉按“基础信息、价格、接口、性能、应用”组织，避免每个小节再套卡片；桌面宽度稳定，移动端全宽。
- 搜索参数、筛选、分组倍率、计价单位、视图模式和模型详情行为全部保持不变；详情深链或独立详情页返回时必须恢复原筛选与滚动上下文。

#### 使用趋势 `/rankings`

- 移除与定价页重复的径向渐变和大号居中 Hero。
- 顶部为左对齐标题、数据说明和右侧周期分段控件；只展示接口真实返回的周期与数据。
- 模型趋势、供应商占比和涨跌变化采用连续分析画布：桌面以 `8 + 4` 或 `7 + 5` 栅格组合，移动端按阅读顺序纵向排列。
- 图表使用稳定多色序列，绿色只代表主系列或正向状态；图例、轴标签、tooltip 与空状态在深浅主题均可读。
- 触屏设备不能依赖 hover tooltip 才能读取数据；关键排名与数值同时提供可扫描列表或表格等价内容。
- 骨架屏必须匹配最终图表尺寸；错误态使用开放式边框区域和重试入口，不用大圆角虚线卡。

#### 关于、协议与自定义内容

- Markdown 阅读宽度控制在 `760–820px`，正文至少 `16px/28px`，标题、正文、表格、代码与链接形成稳定排版层级。
- 关于页空状态使用小型图标、说明和项目链接，不使用 `96px` 装饰图标；New API、QuantumNous、One API、许可链接保持完整。
- 协议未配置时显示明确标题、原因与返回入口，不以卡片套卡片呈现。
- 自定义 HTML 与 URL 分支保持原始内容和 iframe `sandbox`；外层只负责公共页头、高度、安全区、加载与错误回退。iframe 可视高度使用 `100dvh - 页头 - 页面标题带`，不得进入固定页头区域。

#### 错误页

- `401/403/404/500/503`、根级错误与认证区嵌入错误共用同一内容组件，通过独立全屏和后台嵌入两种外壳呈现；后台嵌入态不得再次占满 `100svh`。
- 状态码是辅助视觉，实际错误标题使用页面 `h1`。恢复操作必须真实可用：`401` 去登录，`403` 返回，`404` 回首页，`500` 重试并保留问题反馈，`503` 刷新。
- 不使用插画、漂浮卡片或幽默文案。未认证时返回登录，已认证时优先返回控制台，其他情况返回首页。
- 没有行为的“了解更多”等按钮必须删除；错误说明自然换行，不使用强制 `<br>` 破坏长翻译。

### 16.8 认证页面规范

- 表单标题只描述当前任务，如“登录”“创建账户”“找回密码”“输入验证码”；不增加产品功能列表或营销口号。
- 字段标签始终可见，不用 placeholder 代替 label。密码显示、验证码发送、提交、OAuth 与 Passkey 保持清晰顺序。
- OAuth 提供商超过三个时使用等宽列表或两列网格；品牌图标保持原始含义，不改成统一绿色圆形图标。
- 条款勾选、验证码、注册关闭、邮箱验证、重复提交、网络失败和服务端字段错误均需有明确状态。
- 主要提交按钮占满表单宽度；输入和主按钮高 `48px`，其他交互点击区不小于 `44 x 44px`，次级入口使用文本链接。
- OTP 使用不小于 `44 x 44px` 的稳定单字符输入槽，粘贴、退格、方向键和自动前进均保持可用；流程过期时不再展示可提交表单，错误出现时页面不得跳动到看不见提交区。
- Turnstile 或同类外部验证控件使用可适应窄屏的尺寸模式，不得在 `320px` 页面产生横向溢出。
- `/oauth` 与 `/oauth/$provider` 使用同一套处理中、成功、拒绝、失败、超时和绑定窗口失联状态，不允许任何回调阶段返回空白页面。
- OAuth 回调与安全验证使用相同尺寸的状态图标和反馈结构，不使用 `rounded-2xl` 大图标容器。
- 法律同意只保留一个权威交互区；不得同时出现强制勾选和重复的“点击即同意”底部提示。协议、邮箱与密码显隐等可见文案必须全部进入 i18n。
- 返回首页、语言与主题入口必须可键盘访问；移动端输入字号不低于 `16px`，避免浏览器自动放大。

### 16.9 用户控制台规范

#### 概览 `/dashboard/overview`

- 首屏顺序为账户与余额摘要、接入进度、快捷操作、公告与服务信息。只展示真实接口数据，不新增模拟运行指标。
- 摘要采用共享边框的指标带或紧凑面板，不形成多层卡片网格；趋势线只用于有时间序列的数据。
- 新用户接入引导保留“创建密钥、复制接口地址、发送请求”三步，但文案面向调用者，不使用渠道配置术语。
- 快捷操作使用图标加短标签，入口真实可用；移动端保持两列或列表，长翻译不得截断。

#### 用量分析 `/dashboard/models|users|flow`

- 筛选与时间范围置于标题栏或单一工具栏，图表偏好等低频操作进入菜单或对话框。
- 统计指标、分布图、趋势图和性能面板按分析顺序组织，面板边框统一；禁止图表卡片内部再套指标卡。
- 敏感数据显示开关必须同时更新可见文本和 `aria-pressed`/可访问名称。
- 图表在 `320px` 下优先减少轴标签密度；确实需要比较时只允许图表内部横向滚动，不允许页面溢出。

#### API 密钥与请求记录

- `/keys`、`/usage-logs/*` 共享“标题 + 主操作 + 筛选工具栏 + 数据区 + 分页”骨架。
- API 密钥页突出创建、复制、状态、额度、分组和到期时间；完整密钥继续受现有遮罩与验证逻辑保护。
- 请求记录优先保留时间、模型、状态、用量、费用和详情入口；筛选器不得挤占首屏大面积空间。
- 简单实体在移动端使用现有语义卡片列表；需要横向比较的日志表使用局部滚动并固定关键列，不能把每个单元格拆成冗长卡片。
- 批量操作只在有选择时出现，并保持选中数量、取消和危险操作的明确关系。

#### 余额与充值 `/wallet`

- 顺序固定为余额摘要、充值主流程、订阅方案、兑换码/账单、返利信息；不存在的功能模块不保留空白占位。
- 充值金额、到账金额、折扣和支付方式必须在确认前同时可见，数字右对齐并使用等宽数字。
- 支付方式是选择控件，不做装饰卡片墙；选中、不可用、处理中和失败状态必须清晰。
- 移动端采用单列，最终付款操作靠近金额摘要并考虑安全区；不创建会遮挡第三方支付返回的固定层。

#### 账户与安全 `/profile`

- 个人信息、语言、密码/绑定、会话、Passkey、双因素认证、签到与侧栏偏好按“账户、安全、偏好”分组。
- 桌面允许主列加辅助列，但不在辅助列中堆叠多张悬浮卡；使用连续分区与分隔线。
- 安全操作显示当前状态与最近变化；删除账户、停用二次验证和撤销会话继续使用明确的危险确认。

#### Playground 与 Chat

- 作为生产工具界面处理，不继承公共页的编辑式大标题。
- 保留输入区、参数面板、消息流、流式响应、附件、工具调用和会话导航等既有行为。
- 桌面保持主工作区优先；参数面板可折叠。移动端输入区固定在安全区上方，消息正文和代码块各自局部溢出。
- 不通过机器人、发光头像、渐变消息气泡强化 AI 风格；用户与系统状态依靠标签、边框和排版区分。

### 16.10 管理控制台规范

- 管理页面保持“工具栏 + 高密度表格/表单 + 抽屉或对话框”的操作型结构，不改造成营销式卡片页面。
- 渠道、模型、用户、兑换码和订阅列表统一表头高度、行高、选择列、状态标签、批量操作、分页与移动降级。
- 状态标签使用文字和低饱和底色；正常、禁用、警告、错误的颜色含义全站一致。
- 新建与编辑优先沿用抽屉；短确认与单一选择使用对话框；复杂配置不得塞入小对话框。
- 抽屉内按稳定业务概念分节，桌面操作区固定在底部，移动端全宽并考虑安全区；保存、取消和脏状态提示必须同时可见。
- 系统设置继续使用钻入式侧栏。设置页以章节导航、表单分组和底部保存状态为主，不给每个字段组套一张卡。
- 危险操作必须保留二次确认、对象名称、影响范围和不可逆说明；视觉同步不得弱化权限与风险提示。
- 管理员专属术语不下放到普通用户界面；角色不可访问的入口继续由现有权限和路由守卫控制。

### 16.11 响应式与状态体系

#### 断点

- `< 768px`：移动工作流。公共导航使用全屏菜单，应用侧栏使用抽屉，页面操作收进菜单，表单单列。
- `768–1279px`：紧凑工作台。应用侧栏可折叠，公共页内容收窄；定价筛选使用抽屉而不是强行保留侧栏。
- `>= 1280px`：完整工作台。显示常驻筛选栏、双列设置或宽图表布局。

#### 表格降级

- 实体浏览型表格可转为移动列表：API 密钥、渠道、用户、兑换码、订阅。
- 比较型表格保留表格语义并局部横向滚动：定价、请求日志、模型性能、系统信息。
- 任何模式都必须保留排序、筛选、选择、批量操作、详情和分页能力；不得只为适配手机删除关键列而不给详情入口。

#### 统一页面状态

| 状态 | 呈现规则 |
| ---- | -------- |
| 加载 | 骨架与最终结构同尺寸，避免大范围布局跳动；减少动态效果时关闭 shimmer |
| 空数据 | 说明“当前没有什么”和一个最相关操作，不展示营销插画 |
| 无结果 | 保留当前筛选摘要，提供清除筛选，不与业务空数据混淆 |
| 错误 | 展示可理解原因、重试和必要的错误标识，不直接暴露敏感响应 |
| 无权限 | 明确权限不足和返回路径，不渲染不可用操作 |
| 禁用 | 控件状态、原因和可访问属性一致，不只降低透明度 |
| 长内容 | 自然换行、局部滚动或详情展开，页面级禁止横向溢出 |

### 16.12 交互与可访问性

- 所有页面保留 `header`、`nav`、`main`、`section`、`form`、`table` 等语义结构，并确保每页只有一个主内容区域。
- 图标按钮必须有可访问名称；装饰图标 `aria-hidden="true"`。移动与桌面焦点顺序必须与视觉顺序一致。
- 焦点态使用清晰 `2px` 外圈或等效高对比样式，不能只依赖颜色细微变化。
- Tabs、分段控件、菜单、抽屉、对话框、筛选器和数据表选择状态必须支持键盘并暴露对应 ARIA 状态。
- 正文对比度满足 WCAG 2.1 AA；状态、图表系列和表单错误不得仅靠颜色区分。
- 运动只用于路由过渡、抽屉、模态和状态变化；普通卡片不抬升，数据表不依赖逐行入场才能理解。
- `prefers-reduced-motion` 下关闭非必要位移、缩放、shimmer 和图表入场，功能状态仍完整可见。

### 16.13 工程边界与组件责任

实现时先处理共享责任，再处理页面例外：

| 文件族 | 责任 |
| ------ | ---- |
| `styles/theme*.css` 与页面根作用域 | 语义变量、主题兼容、圆角和状态色，不写页面业务布局 |
| `components/layout/**` | 公共、认证、应用三种骨架，页头、侧栏、标题栏与滚动职责 |
| `components/data-table/**` | 工具栏、表格、移动列表、分页、空态与局部溢出 |
| `components/ui/**` | 按钮、输入、Tabs、Badge、Dialog、Drawer 等跨页面几何与状态 |
| `features/pricing|rankings|about|legal|errors/**` | 公共页面信息架构和页面专属内容 |
| `features/auth/**` | 认证表单与状态，不复制 AuthLayout 样式 |
| 用户与管理 `features/**` | 页面专属数据组织；共享模式必须复用布局和表格组件 |
| `i18n/locales/*.json` | 七语言文案同步，不删除既有仍被使用的键 |

工程原则：

- KISS：先调整现有布局与语义变量，不为视觉同步引入新的状态管理或渲染框架。
- DRY：页面骨架、工具栏、表格移动降级和状态组件统一实现，禁止逐页复制大段 Tailwind 类。
- YAGNI：只实现文档列出的页面状态，不预留未确认的品牌站、客户案例、套餐营销或实时监控功能。
- SOLID：共享组件负责结构与交互契约，feature 组件负责业务数据和页面内容；视觉组件不得读取无关业务状态。

### 16.15 实施顺序

1. 建立逐路由基准截图和功能不变量清单，确认访客、用户、管理员与超级管理员视图。
2. 完成第 16.14 节代表页面概念图并取得确认，锁定公共、认证、工作台三套视觉系统。
3. 实现根作用域变量和共享骨架：公共页头、认证布局、应用页头/侧栏、`SectionPageLayout`。
4. 实现公共页：模型与价格、使用趋势、关于、协议和错误页。
5. 实现完整认证流程并验证所有重定向、验证码、OAuth 和关闭状态。
6. 实现用户核心页：概览、用量分析、API 密钥、请求记录、余额与充值、账户与安全。
7. 实现 Playground/Chat 的品牌同步与移动输入体验，不改消息和流式协议。
8. 通过共享表格、表单和抽屉模式同步管理页面，再处理必要的页面例外。
9. 处理安装、自定义内容、iframe 与全站加载/空/错误/无权限状态。
10. 补齐七语言、回归测试、类型、lint、格式、构建和多视口浏览器验收。

每一阶段必须独立可交付，不允许先全局替换颜色和圆角、再长期保留页面结构不一致的中间状态。

### 16.16 验收矩阵

| 页面族 | 代表路由 | 必验状态 | 功能不变量 |
| ------ | -------- | -------- | ---------- |
| 公共 | `/pricing`、`/rankings`、`/about` | 加载、空、正常、筛选、详情、外部内容 | 动态导航、搜索参数、模型详情、自定义内容分支 |
| 认证 | `/sign-in`、`/sign-up`、找回、重置、`/otp`、OAuth | 默认、字段错误、提交中、多认证、关闭状态 | 重定向、条款、验证码、注册与认证开关 |
| 用户控制台 | `/dashboard/*`、`/keys`、`/usage-logs/*`、`/wallet`、`/profile` | 空、正常、大数据、筛选、抽屉、危险操作 | 权限、请求、分页、导出、余额和密钥操作 |
| 交互工具 | `/playground`、`/chat/*` | 初始、流式、错误、长内容、移动输入 | 会话、流式响应、滚动、附件与快捷操作 |
| 管理 | `/channels`、`/models/*`、`/users`、`/system-settings/*` | 表格、表单、批量操作、无权限、确认 | 角色隔离、配置保存、危险操作与审计语义 |
| 特殊 | `/setup`、协议、错误、自定义内容 | 嵌入、超长内容、空配置、`404/500` | iframe 沙箱、自定义内容和项目归属 |

统一验收维度：

1. 视口：`1440 x 900`、`1280 x 800`、`1024 x 768`、`768 x 1024`、`430 x 932`、`390 x 844`、`360 x 800`、`320 x 568`；认证与错误页额外检查 `320 x 320` 极矮视口。
2. 模式：浅色、深色，以及至少一个非默认用户主题预设。
3. 身份：访客、普通用户、管理员、超级管理员；不可访问页面必须验证路由守卫。
4. 语言：七种语言全部检查标题、工具栏、表格、对话框和最长表单说明，无裁切和页面横向溢出。
5. 操作：键盘导航、焦点恢复、抽屉/对话框关闭、筛选、分页、表格选择、移动菜单和安全区。
6. 工程：受影响测试、`bun run i18n:sync`、类型检查、涉及文件 lint、格式检查与生产构建全部通过。
7. 视觉：每个代表页面用浏览器截图与已批准概念图逐项比较；颜色、标题、容器、密度、图标、响应式和状态无未说明偏差。
